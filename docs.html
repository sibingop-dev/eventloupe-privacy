Getting started

Eventloupe is a Chrome DevTools extension. It's launching on the Chrome Web Store soon, so there's no public download yet.

Open the panel

Chrome has no way for an extension to open DevTools for you, so there are three steps:

  1. On the page you want to inspect, press ⌘ ⌥ I on a Mac or Ctrl Shift I elsewhere. F12 works too.
  2. Select the Eventloupe tab, next to Network and Console. If it's hidden, use the » menu.
  3. Keep DevTools open while you browse. Events appear as the page fires them.

What you'll see

  • The feed: every event in time order, grouped when the same event fires in a burst.
  • The detail pane: Pipeline, Normalized, Payload, Ecom, Validation and Request views for the selected event.
  • The issues panel and health score: what needs attention first, grouped by severity.

Reading an event

Three states, never two

StateExampleMeaning
ObservedhttpStatus: 204The request was seen and the response came back clean.
FailedhttpStatus: 500The request was seen and delivery was confirmed to have failed.
UnknownhttpStatus: nullNot observable from the browser. It is never treated as success or failure.

The six stages

Every event is traced through the same pipeline. Each stage is marked observed, failed or unknown.

StageWhat it looks atUnknown when
ApplicationThe page's own call: a dataLayer push or an SDK call.The call ran before Eventloupe could hook it.
Tag ManagerContainer load, and the dataLayer push that came just before the tag fired.No container was observed.
SDK invocationThe platform SDK call, hooked inside the page.The SDK runs where the hook can't reach, such as a sandboxed iframe.
NetworkThe request the browser sent: endpoint, method, parameters, body.The browser didn't expose the request.
ResponseHTTP status and timing.The status isn't observable, for example a beacon.
CorrelationDuplicates, funnel steps and browser/server pairs.No related event was observed.

Confidence and severity are separate

Confidence is how much evidence supports an event. Severity is how serious a finding is. They never imply each other: low confidence isn't an error, and high confidence isn't success. A fully observed event can still have a critical finding if delivery was confirmed to fail.

Diagnostic codes

Every finding has a code like EL1003. Codes are permanent identifiers: the message may be reworded, but the code never changes. They come from fixed rules, so the same input always gives the same result, and a code never fires on missing evidence alone.

Examples

EL1001Medium

Network request not observed

The JS API call was intercepted, but no matching network request was seen.

FixCheck whether a consent manager or ad blocker is suppressing the request.

EL1002Critical

HTTP 4xx client error

The tracking server rejected the request, so the event was lost.

FixCheck the payload for malformed parameters or an invalid pixel ID.

EL1003Critical

HTTP 5xx server error

The tracking server returned an error, so the platform failed to record the event.

FixThis is platform-side. Retry, or check the platform's status.

EL2003High

Event ID mismatch

The event_id in the JS call doesn't match the one in the network request.

FixPass the same event_id to fbq() and to the CAPI server call.

EL4002Medium

ad_storage denied on a conversion

The conversion may not be attributed to the right ad click.

FixMake sure Consent Mode is configured correctly for your consent platform.

EL4012Critical

Consent default set after config

gtag("consent","default") fired after gtag("config"), so tags may have fired with the wrong consent state.

FixMove the consent default before any config call, ahead of your tag manager.

Eventloupe reports what it observed. A request it doesn't see is "not observed", and the suggested fixes name likely causes without claiming one.

Permissions

Eventloupe asks for the following Chrome permissions. None of them lets it send data anywhere.

PermissionWhy it is needed
<all_urls>To inject the tracking interceptor into any website you open for inspection.
webRequestTo observe (not block or modify) network requests from tracking pixels that fire before DevTools is opened.
scriptingTo inject a small hook into the inspected page to intercept dataLayer pushes and SDK calls.
tabsTo read the current tab's URL so events are grouped by page.
storageTo save your alert-rule preferences locally in your browser.

FAQ

Why does an event say "unknown"?

Because the browser didn't expose the evidence, for example a response to a beacon. Eventloupe records that as unknown instead of guessing success or failure.

Why doesn't it say "blocked by an ad blocker"?

It can't tell. It sees that an SDK call happened and no matching request followed, so it reports "not observed" and suggests an ad blocker or consent manager as a likely cause to check.

Does Eventloupe block or change any requests?

No. It observes requests and never blocks or modifies them.

Does it send my data anywhere?

No. Captured events stay in your browser. See the privacy policy.
